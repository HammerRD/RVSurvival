# Technical architecture
One runtime C++ module with Core, Player, Interaction, UI, Vehicles, Inventory, Survival and Resources boundaries. Equipment, Crafting, AI, World, Encounters, Factions and full Save systems remain future gate work, not speculative managers.

GameInstance is a campaign/session lifecycle extension point. GameMode chooses pawn/controller/state/HUD classes and owns server rules. GameState remains a typed framework extension point; PlayerState carries authoritative survival needs across pawn possession. Character composes Camera, Interaction, Inventory and the reusable passenger reference frame while retaining native CharacterMovement network prediction. PlayerController remains the ownership/input framework boundary.

IRVInteractable offers side-effect-free permission/text/duration queries and authority-only start/complete/cancel events. URVInteractionComponent performs local focus queries and authoritative retraces. RVTestInteractable owns a replicated counter. Prototype Canvas presentation reads prompt, inventory and resource state; the UMG survival widget remains separate. Gameplay never depends on the HUD.

Enhanced Input mappings are transient assets created per pawn, retained by UPROPERTY, installed only in its local-player subsystem, and removed at teardown. No plugin beyond Enhanced Input is needed for Gate 1. Chaos, World Partition, Gameplay Tags and Data Assets enter the architecture when their concrete gate requires them.

Gate 2 adds ChaosVehiclesPlugin and the ChaosVehicles/PhysicsCore module dependencies. ARVVehicleBase extends Unreal's AWheeledVehiclePawn and owns seat lifecycle, safe exit queries and input routing. ARVMotorhome composes named driver/passenger URVVehicleSeatComponent default subobjects, a chase camera and clearly labeled prototype primitives. Additional seats use the same component/lifecycle path. ARVVehicleEntryPoint adapts each seat to IRVInteractable; the Gate 1 interaction component is unchanged.

URVVehicleMovementComponent uses supported Chaos wheeled simulation on authority and native rigid-body replication on clients. ARVPlayerController owns driving/exit RPCs, validates through the assigned seat, and releases the RV before the default disconnect path can destroy the possessed pawn. The survivor persists while driving; passengers retain survivor possession with movement/collision disabled and attachment to a seat. Survivor and vehicle mappings are removed on unpossession/controller changes as well as teardown.

BP_PrototypeMotorhome contains rig, physics-asset, animation and wheel-bone configuration. Gameplay does not load the off-road art asset by path. Primitive prototype shell/cab configuration is exposed through native component properties; replace these and the rig in content when production art arrives. Gate 2 did not implement moving interiors; the Gate 3 reference-frame boundary is described below. Future survival subsystem managers remain unimplemented.

## Gate 3 moving mobile-base foundation (accepted)

ARVInteriorMotorhome extends ARVMotorhome with content-configured visual parts, simplified query collision, tagged passenger floors and fixed station locations. It leaves driver possession, seat authority and Chaos control routing in the accepted vehicle classes. `/Game/Vehicles/Gate3/BP_ClassCMotorhome` uses the purchased `/Game/RV` Class C assembly as its visual and dimensional basis. All 54 mesh parts remain independent; the invisible skeletal Chaos rig, project-side chassis physics asset and wheel configuration are replaceable. Vendor art has no gameplay collision. Doors/compartments/wheels/steering are separate presentation parts, without new survival systems or detailed dressing.

URVPassengerReferenceFrameComponent observes tagged native CharacterMovement bases. Unreal carries the capsule using based movement, base-relative network moves, prediction and smoothing; walking passengers are not attached or warped every tick. The component applies reversible interior movement policy and records local position, base/frame changes and client corrections. URVCharacterMovementComponent only adds correction instrumentation. It does not replace the native movement solver or accept client transform RPCs.

Six ARVInteriorStation placeholders reuse the Gate 1 interaction contract and replicated completion counter: workbench, medical, kitchen/food preparation, storage, electrical/power and navigation/radio. They are attached fixed endpoints, not implementations of crafting, treatment, cooking, containers, electrical power or navigation. Future equipment can compose behavior behind the existing interface, with authoritative permission checks and replicated state. Layout and station configuration belong to content, not hard-coded purchased mesh paths in gameplay.

The motorhome remains a mobile survival base. Later gates must preserve local interior coordinates and fixed interaction endpoints for food/water, hunger/thirst, fatigue/sleep, injuries/medicine, generator/solar/battery power, maintenance/repairs, crafting and long-term storage. Those systems are deliberately absent here. Additional standing passengers should use the same per-character component and native bases rather than a vehicle-owned list of transform overrides.

## Gate 4 inventory integration (accepted Gate 4)

Inventory now has its own C++ boundary under Public/Private/Inventory: Primary Data Asset definitions, identified lightweight FastArray records, shared inventory/container capacity transactions, and separate interactable pickup/storage actors. The survivor owns its inventory component; vehicle possession and the passenger movement code remain unchanged. Inventory presentation stays in the temporary HUD. Full persistence/equipment/crafting systems are outside this gate. See INVENTORY.md and GATE_4_VALIDATION.md for the implemented model and current acceptance status.

## Gate 5 needs framework boundary (accepted)

URVNeedsComponent is a replicated PlayerState subobject, independent of character/vehicle possession. FRVNeedsState is reflected scalar data with SaveGame-marked persistent fields; transient rest reservations are not persisted. URVNeedsProfile is a Primary Data Asset for normal tuning. Authority applies hour-based gameplay rules; Unreal owns replication, RPC transport, component ticking, timers and object lifetime. Native CharacterMovement retains prediction/moving-base handling; a derived speed query applies critical-need policy without rewriting its solver.

Framework review: GAS is deferred for Gate 5's simple slow scalar simulation, not replaced by a custom effect framework. Before future injuries, bleeding, medication or stacking/timed effects, reassess PlayerState-owned ASC/AttributeSets/GameplayEffects (Epic Lyra pattern). Native RepNotify notifications and Gameplay Tags expose current derived status. New survival presentation uses UMG; accepted inventory Canvas controls remain pending a later UI-focused migration. No CommonUI menu framework or Lyra experience/game-feature architecture is imported without a demonstrated need.

Future region streaming must not reset PlayerState-owned needs or pause metabolic updates merely because the current pawn is an RV. CopyProperties prepares scalar transfer; actual seamless travel and offline progression are unimplemented and unvalidated.

## Gate 6 machine resource boundary (accepted after live validation)
New Resources boundary: URVFuelComponent, URVBatteryComponent, URVElectricalComponent, URVEnergyProfile and reflected tuning/load/flow records. ARVSystemsMotorhome composes these with existing purchased RV presentation, rig, collision, seats and reference-frame architecture. It does not embed inventory or passenger movement implementations. ARVResourcePoint adapts the accepted held-interaction contract; ARVPlayerController owns validated intent RPCs and Enhanced Input controls; existing HUD reads replicated state.

Reusable fuel/battery components use litres and watt-hours. The RV-specific bus converts seconds to hours once, allocates nonbattery sources in configured priority, supplies per-domain prioritized loads and applies bounded battery fallback/charging. Fuel-can metadata and typed runtime fields extend the accepted identified item model rather than creating actor inventories for every can. Noise/power delegates and optional workstation required-load IDs expose clean later integrations.

GAS/Lyra experience/game-feature machinery is not needed for resource balances; native components, Data Assets, tags, replication and TimerManager cover engine concerns. Medical effects/stacked status still warrant the separately documented future GAS review. CharacterMovement, Chaos physics and accepted inventory transactions remain intact. Supported Chaos torque adjustment is the sole propulsion-fuel gate.

Persistent snapshots will eventually include tank litres/type/capacity configuration, per-item GUID/fuel amount/revision, each battery's energy/capacity, requested generator/idle/load state, source profile/priority and environmental input configuration. Runtime endpoint pointers/flow telemetry are transient presentation/access state, not persistence identity. Full vehicle identity/save/load/seamless regional streaming remains future work, not claimed implemented.

Gate 6 seam regression hardening: URVPassengerReferenceFrameComponent uses supported CharacterMovement bBaseOnAttachmentRoot only while on tagged walkable RV floor. Floor detection/collision remains modular; movement and replication share the rigid attachment root across adjoining floor pieces. Reference-frame eligibility uses the actual CurrentFloor hit, not an assumption that the common root itself is a floor. Exit and EndPlay restore the previous native setting. No transform forcing, custom prediction transport or engine patch is introduced. Expanded role/network regression evidence is recorded in GATE_6_VALIDATION.md.

Gate 6 final status: ACCEPTED on 2026-10-06. Final resource, separate-process/emulated moving, stress, prior-gate regression and saved-asset evidence is in GATE_6_VALIDATION.md. Gate6FuelElectricalTest is saved with 65 actors/14 pickups; the copied inert can fixture was removed only from this map. Prior maps and all 108 vendor source files remain unchanged. Gate 7 is not authorized or implemented.

## Gate 6 reusable interior interaction refinement
URVRestPoseComponent owns the explicit replicated bed presentation/anchor and validated stand-up restoration. ARVRestPoint owns configurable physical lying/camera/wake offsets and occupancy; URVNeedsComponent owns rest/sleep gameplay state. ARVInteractiveDoor implements the accepted interaction interface with configurable purchased mesh children, replicated hinge state and safe query collision. URVInteractionTargetPresentationComponent centralizes hidden surface-target rendering and optional development visualization.

ARVInteriorMotorhome composes these systems and exposes capsule/floor-safe aisle selection; vehicle physics remains independent of art. Station counters and container/panel views remain stateless, avoiding six duplicated movement/camera-lock implementations. No vendor source mesh was edited. Native Actor Components, RepNotifies/RPCs, Enhanced Input and CharacterMovement are retained.
## Gate 6 second-refinement architecture notes

URVLadderClimbComponent uses supported CharacterMovement MOVE_Flying, plane constraints and AddMovementInput for a parked, reserved ladder rail; ARVLadder validates rail/ground placement and composes a temporary vehicle drive lock. No Mover migration or custom movement replication is introduced. Roof traversal remains disabled pending safe roof collision.

ARVRestPoint exposes an invisible configurable query surface and optional named cushion support. Lying placement validates that physical support and all remaining blockers; wake uses the reusable interior placement policy. The prototype pose is presentation only. Generated purchased visual components are reacquired from actual ownership rather than relying on a transient tracking array after a saved map reload.
