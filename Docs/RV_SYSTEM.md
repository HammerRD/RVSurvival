# RV system plan
Gates 1–4 are accepted; Gate 5 core survival validation is accepted; see GATE_5_VALIDATION.md. Gate 2 isolates supported Chaos Vehicles behind ARVVehicleBase and URVVehicleMovementComponent, and composes ARVMotorhome with authoritative driver/passenger URVVehicleSeatComponent instances. Gate 3 uses a reusable passenger reference-frame component around native CharacterMovement.

The preserved Gate 2 fallback content configuration is `/Game/Vehicles/BP_PrototypeMotorhome`. It uses Epic's installed UE vehicle-template off-road rig/physics/animation and a primitive shell labeled PROTOTYPE RV. The RV prototype has 3500 kg mass, automatic gears, rear-wheel drive and basic W accelerate, S brake/reverse, A/D steer, Space handbrake and E exit controls. Handling and physical body dimensions are prototype settings, not production Class C tuning. Test map: `/Game/Maps/Gate2VehicleTest`; Gate1Test is preserved.

Each seat defines a label, driver role, local entry offset and preferred exit offset. Runtime entry panels reuse the accepted 0.5-second interaction hold. Authority prevents double occupancy. Driver possession switches to the RV; the original survivor remains attached to its seat. Passengers retain survivor possession, remain attached, and cannot walk/jump or drive from a passenger seat. Driver exit waits for the entry key to be released after possession. Stationary E exit checks ground slope, height and capsule clearance, tries alternate roadside candidates, restores walking/possession and frees occupancy. If all candidates are unsafe, the seat remains occupied. Entry/exit speed limit is 150 cm/s. Disconnect releases the seat and parks the surviving shared vehicle.

The vehicle base, seat components and entry adapters contain gameplay; the Blueprint configures presentation and rig/tuning. Replacing art requires configuring a suitable skeletal physics rig/wheels and adjusting seat/entry/exit offsets, without rewriting networking or seat assignment. No engine, fuel, cooling, battery, electrical, water, storage or other future gameplay subsystem is implemented in Gate 2.

Gate 3 proved two networked players, highway-speed driving, front-to-rear passenger walking and stable based movement. There is no separate static interior. These accepted results remain the regression foundation. Current authorized work is Gate 5 only; combat/world systems remain deferred.

Future systems separate fuel, individual mechanical conditions, automotive power and house power; no generic RV health. Cooling dependencies and empty-fuel propulsion blocking belong to later gates.

## Gate 6 fuel/electrical foundation (authorized 2026-10-06; accepted after live validation)
Gate6FuelElectricalTest uses a separate BP_ClassCSystemsMotorhome derivative of the refined Gate 5 RV. ARVSystemsMotorhome only composes fuel/battery/electrical components, two representative lights and fixed query endpoints; accepted Chaos and seat code is retained. The passenger component additionally uses the native attachment-root basing option to stabilize floor seams, with normal outside settings restored. All earlier maps, fallback assets and 108 vendor files are protected.

URVFuelComponent stores litres, capacity and fuel compatibility. Main tank prototype: 200 L capacity / 150 L start. A separate configurable 30 L / 20 L generator tank is available; normal profile uses the main tank with a 20 L pickup reserve. Driver presence runs the prototype engine automatically; EngineIdle is an explicit parked request. No starter/dead-battery or mechanical-failure simulation is added. Idle/throttle/road use influences burn. The supported Chaos SetMaxEngineTorque boundary removes propulsion at zero fuel and restores configured torque after fuel returns, preserving braking, steering and possession.

URVBatteryComponent instances keep house (2400/1800 Wh, 800 W maximum charging, 1500 W maximum discharge) separate from chassis (800/600 Wh, 250 W charging). URVElectricalComponent applies the normal Primary Data Asset's rates, prioritized domain loads and source flow. Normal sources: generator 1800 W / 1.2 L/hour; alternator 500 W house + 250 W chassis; solar 300 W peak times authoritative available-input scalar (starts zero); optional external/shore 2000 W input. Defaults are provisional, not measured production specifications.

Nonbattery source order is configurable (normal shore, generator, alternator, solar); battery remains fallback. Loads receive allocated energy before surplus charges batteries, under battery charge/discharge ceilings; unused generation is curtailed. Chassis alternator energy supplies chassis loads before charging its own battery. This is an ideal usable-energy bus, without AC/DC conversion, voltage/wiring, chemistry or degradation simulation.

Representative loads: interior lights 24 W, refrigerator 90 W, powered equipment 120 W. Navigation can require PoweredStation through configuration; hand-tool/workbench/storage and the panel itself remain usable without electricity. Refrigerator powered state and power/noise change delegates are future hooks, not food spoilage or AI. Generator running/noise is shared machinery state and persists independently of the player who switched it on.

The existing Power marker opens the composed control panel on Gate 6 vehicles while retaining its accepted interaction count. H lights, J generator, K refrigerator, L powered equipment, O engine idle; Escape closes the monitor. Enhanced Input Started actions dispatch owned controller requests. The prototype HUD only displays replicated resource state. Fuel-fill interaction is a clearly project-side driver-side marker (-155,-137,120) cm; no separately confirmed vendor fuel-door mesh is modified or implied. Hold E at the fill, select an owned can in inventory and press F. Use the accepted exterior fluids/service compartments for cans. See GATE_6_VALIDATION.md for executed tests and limits.

Gate 6 seam regression hardening: URVPassengerReferenceFrameComponent uses supported CharacterMovement bBaseOnAttachmentRoot only while on tagged walkable RV floor.
